# review-post

리뷰 결과를 GitHub PR에 게시하는 스킬. **무엇을 올릴지는 항상 사용자가 정하고**, 게시 전에 미리보기를 보여 주고 승인을 받는다.

> 사람용 소개 문서. 스킬 동작은 `SKILL.md`가 정한다.

## 호출

```
/review-post comment <게시 목록 파일> [<id> ...] [--dry-run]
/review-post reply <문서 폴더 | 문서들> [--dry-run]
```

명시 호출 시에만 동작한다. `comment`에서 id를 안 주면 목록을 보여 주고 번호로 고르게 한다.

## 모드

| 모드 | 입력 | 게시 |
|---|---|---|
| `comment` | 게시 목록 파일(`/self-review` 원장도 가능) | 고른 지적을 코드 줄(범위)마다 인라인 코멘트로 달고, PR 리뷰 1건으로 묶어 제출 |
| `reply` | `/vet-review` 문서 폴더 | 처리가 끝난 리뷰 링크마다 처리 커밋 답글 1건 |

## 흐름

R0 대상 확인(PR 상태·계정·인용 커밋의 원격 존재) → R1 항목 선택 → R2 줄 사전 검증(`scripts/commentable_lines.py`) → R3 본문 작성 → R4 미리보기·승인 → R5 게시 → R6 게시 URL 기록·결과 보고

## 하지 않는 것

- 기각 사유 답글 게시(사용자가 리뷰 대응 중 직접)
- PR 승인·변경 요청, 스레드 resolve, 라벨·본문 수정, push
- 사용자가 고르지 않은 항목 게시

## 검증 상태

두 모드 모두 dry-run으로 확인했다(게시 없음). `comment` 모드의 실제 게시(묶음 리뷰 API가 줄 범위를 받아들이는지)는 첫 실사용 때 확인한다.
